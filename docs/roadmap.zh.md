# 路线图

[English](roadmap.md) | [简体中文](roadmap.zh.md)

## 阶段一：共享源码工具

已提供 `pkg/format`、`pkg/header`、CLI、针对性测试及可执行示例。
质量检查覆盖 Go 1.27 兼容性、格式、文件头、模块依赖、vet、单元测试、race 测试和 lint。

仓库和生成器共享同一个实现，无需加载应用类型。格式化具有确定性和幂等性，
源码文件头独立维护。

## 阶段二：使用方发布接入

使用方的源码检查和代码生成步骤固定同一个版本，CLI 工具不进入无工具依赖的契约模块。
各使用方发布前，通过 `GOWORK=off` 验证其已发布依赖。

本阶段要求每个使用方能够独立构建，并应用共享策略。接入和发布条件须逐仓库验证，
不能用本地工作区构建结果代替。

## 阶段三：策略维护

每条新规则都需要明确的可读性需求和回归测试。调整策略时须发布新版本，
验证代表性的使用方样本，并说明兼容性影响，以便审查规则变更，由使用方选择升级时机。

## 阶段四：版本与文档交付

已提供稳定 tag 校验、英文版本说明、针对 tag 源码的可复用质量检查、GitHub Releases，
以及从已发布 tag 部署双语文档的流程。

使用方可以固定已发布的模块版本，Pages 展示对应版本的行为说明。
每次发布均需验证对应提交、版本说明和线上站点。
